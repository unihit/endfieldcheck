# 엔드필드 체크리스트 PWA

GitHub Pages 화면 + 기존 Apps Script 저장소를 사용하는 개인용 PWA입니다. Cloudflare·Firebase·추가 서버는 사용하지 않습니다.

배포 예정 주소: https://unihit.github.io/endfieldcheck/

## 기기 연결

앱의 **연결 설정**에 Apps Script `/exec` 배포 주소와 API 연결 키를 입력하고 **연결 확인·저장**을 누릅니다. 실제 배포 주소는 소스에 포함하지 않습니다. 휴대폰과 PC에서 각각 같은 주소와 키를 입력하면 기존 체크리스트를 공유합니다.

키는 기기의 localStorage에 보관하고 POST 본문으로 Apps Script에만 전송합니다. 키를 URL·GitHub·서비스 워커 캐시에 넣지 않습니다. 브라우저에서 키를 읽을 수 있으므로 개인 기기에 사용하세요. 다른 unihit.github.io 앱과 같은 출처를 공유합니다.

## 동기화

- 체크를 기기에 먼저 기록한 뒤 서버에 전송합니다. 실패하면 대기 상태를 유지합니다.
- 화면이 보이는 동안 30초마다 조회하고, 앱 복귀·재연결 시 재시도합니다.
- 앱이 닫힌 동안에는 전송하지 않습니다. 다음 실행 시 전송합니다.
- 동일 항목은 서버에서 마지막으로 처리한 변경을 적용합니다.
- 지난 기간·삭제된 항목의 대기 변경은 적용하지 않고 안내합니다.
- 목록 편집·디스코드 설정을 열어둔 동안에는 자동 조회를 멈춥니다.
- 처음 온라인으로 화면과 목록을 불러온 뒤 오프라인 사용이 가능합니다.
- 연결 해제는 기기의 키와 저장 목록을 지웁니다. 서버 데이터는 유지합니다. 미전송 체크가 있으면 먼저 동기화해야 합니다.

## Apps Script API 확장

기존 API는 조회·체크를 지원합니다. 목록 편집·디스코드 설정을 사용하려면:

1. 기존 `doPost`, `handleChatApi_`, `routeChatAction_` 함수 3개를 `AppsScript-API-extension.gs`로 교체합니다. 중복 선언하지 마세요.
2. 기존 `CHAT_API_TOKEN` 하드코딩 선언을 삭제하고 프로젝트 설정의 스크립트 속성에 `CHAT_API_TOKEN`을 설정합니다.
3. 기존 웹 앱 배포를 **새 버전**으로 업데이트합니다. 기존 저장 데이터·알림 함수는 유지합니다.
4. 각 기기에 동일한 키를 입력합니다. 공유된 기존 키는 새 값으로 교체하는 것이 좋습니다.
5. `CHECKLIST_URL`을 PWA 주소로 변경하면 디스코드 링크도 PWA를 엽니다.

직접 통신은 URLSearchParams POST를 사용합니다. 기존 배포에서 조회 성공과 `Access-Control-Allow-Origin: *` 응답을 확인했습니다. 로그인 전용 배포에서는 직접 통신이 제한될 수 있습니다. 저장 확인이 불가능한 `no-cors`는 사용하지 않습니다.

## 개발·배포

Node.js 22 이상에서 별도 패키지 설치 없이 `npm test`, `npm run build`, `npm run dev`를 실행합니다.

빌드는 `public/`을 배포용 `docs/`로 복사합니다. Pages 설정은 `main` 브랜치의 `/docs`입니다. 수정 후 빌드 결과를 함께 커밋합니다. 비공개 저장소의 Pages 지원 여부는 GitHub 요금제에 따라 다릅니다.

화면: `public/index.html` · 직접 통신: `public/api.js` · 오프라인 캐시: `public/sw.js`

서비스 워커는 `/endfieldcheck/` 안에서만 동작하며 다른 앱의 캐시를 지우지 않습니다. 자산 변경 시 캐시 버전도 업데이트하세요.

## 설치

Chrome·Edge는 지원되는 경우 앱 설치 버튼 또는 브라우저 메뉴를 사용합니다. iPhone Safari는 공유 → 홈 화면에 추가를 사용합니다.
